# اختبار يدوي قبل النشر

- npm install ثم npm run build؛ حفظ package-lock.json الناتج.
- تشغيل بدون env: الأمثلة تظهر ولا تحدث شاشة خطأ.
- قاعدة جديدة: تنفيذ SQL دون أخطاء.
- تسجيل حسابين A وB وتأكيد البريد وتسجيل الدخول والخروج.
- التحقق من أن لكل حساب profile أُنشئ تلقائيًا.
- A ينشر مشروعًا، B يراه ويعلق ويعجب ثم يلغي الإعجاب.
- منع إعجابين للحساب نفسه على مستوى قاعدة البيانات.
- رفع CSV صغير ثم تنزيله بعد تسجيل الدخول.
- رفض ملف أكبر من 10MB ورفض الملفات التنفيذية.
- الزائر غير المسجل لا يستطيع تنزيل الملفات أو نشر مشروع.
- B لا يستطيع تعديل profile لـ A أو حذف مشاريعه من طلبات API مباشرة.
- B لا يستطيع رفع ملف تحت مسار A أو ربط مرفق بمشروع A.
- حذف مشروع A من واجهته وحذف الملف من Storage.
- اختبار النص العربي والجوال والنصوص الطويلة ورسائل أخطاء الشبكة.
- فحص صلاحيات Supabase ونتائج security advisor وnpm audit دون استخدام force عشوائيًا.
- مراجعة تنظيف الملفات اليتيمة واستعادة كلمة المرور وحذف الحساب قبل فتح التسجيل.
